# RedFlag EU Compliance — static review

## Scope and verdict

**Repository:** `knarayanareddy/redflag-eu-compliance`, pinned to `ae6c6ccc6c5d41da2fa9f97b544ae016235ea6cc` on `main`. **Stage:** early implementation prototype, not a legal assessment. This is a partial static review, not an independent audit or certification. Runtime, builds, tests, browser, container and external services were **not run**. Source files were sampled; the snapshot's first 220 lines of several longer files are not the whole files. See [plan](REMEDIATION_PLAN.md).

The project documents unverified GPSR rules, an absent official Safety Gate corpus, and disabled legal verdicts ([README:6](https://github.com/knarayanareddy/redflag-eu-compliance/blob/ae6c6ccc6c5d41da2fa9f97b544ae016235ea6cc/README.md#L6), [README:58-64](https://github.com/knarayanareddy/redflag-eu-compliance/blob/ae6c6ccc6c5d41da2fa9f97b544ae016235ea6cc/README.md#L58-L64)). This documented state is not proof of configuration-independent enforcement: verified-looking rule metadata can change screening behavior (RF-06). Current rule data and runtime exposure were not independently verified.

## Findings ledger

- **RF-01 — High, confirmed static; legal-use blocker.** README calls the current legal rules “unverified” and says the official alert fixture is absent ([README:58-63](https://github.com/knarayanareddy/redflag-eu-compliance/blob/ae6c6ccc6c5d41da2fa9f97b544ae016235ea6cc/README.md#L58-L63)). Neither GPSR coverage nor recall retrieval quality is established; missing candidates do not establish safety. Keep abstention and disclosures until qualified reviewers verify authoritative sources and representative validation. Confidence high for the documented state, not for legal interpretation.
- **RF-02 — Medium, confirmed static; conditional data boundary.** The README says the “API prototype performs no external model” calls ([README:31](https://github.com/knarayanareddy/redflag-eu-compliance/blob/ae6c6ccc6c5d41da2fa9f97b544ae016235ea6cc/README.md#L31)), while `extract_fields` defaults to `use_model=True` and invokes a caller when both model name and API key exist ([s2:444-469](https://github.com/knarayanareddy/redflag-eu-compliance/blob/ae6c6ccc6c5d41da2fa9f97b544ae016235ea6cc/backend/app/stages/s2_extract_fields.py#L444-L469)). The pinned screen endpoint calls it without overriding that default ([main.py:254-258](https://github.com/knarayanareddy/redflag-eu-compliance/blob/ae6c6ccc6c5d41da2fa9f97b544ae016235ea6cc/backend/app/main.py#L254-L258)). `_call_nano` sends listing text to a configurable base URL with bearer authentication ([s2:305-335](https://github.com/knarayanareddy/redflag-eu-compliance/blob/ae6c6ccc6c5d41da2fa9f97b544ae016235ea6cc/backend/app/stages/s2_extract_fields.py#L305-L335)); the UI says “Input stays in this local prototype” ([App.tsx:195](https://github.com/knarayanareddy/redflag-eu-compliance/blob/ae6c6ccc6c5d41da2fa9f97b544ae016235ea6cc/frontend/src/App.tsx#L195)). Actual configuration and exposure remain unverified, not proof of a leak. Make external processing explicit and opt-in, constrain credential destinations, and update disclosures. Confidence high on code; live behavior unknown.
- **RF-03 — Medium, confirmed static; HTML extraction correctness.** `_VisibleHTML` appends all parser data without tracking `script` or `style` ancestry ([s2:41-75](https://github.com/knarayanareddy/redflag-eu-compliance/blob/ae6c6ccc6c5d41da2fa9f97b544ae016235ea6cc/backend/app/stages/s2_extract_fields.py#L41-L75)), and label matching uses the resulting text ([s2:171-175](https://github.com/knarayanareddy/redflag-eu-compliance/blob/ae6c6ccc6c5d41da2fa9f97b544ae016235ea6cc/backend/app/stages/s2_extract_fields.py#L171-L175)). Hidden script/style text can therefore be treated as listing evidence in HTML mode. This is not a demonstrated live verdict or XSS. Exclude non-visible content with preserved source offsets and test adversarial HTML. Confidence high in the static path; effect on real listings needs reproduction.
- **RF-04 — Medium, unverified risk; package/deployment boundary.** The container copies only `backend/` and invokes `python -m app.main` ([Dockerfile:1-5](https://github.com/knarayanareddy/redflag-eu-compliance/blob/ae6c6ccc6c5d41da2fa9f97b544ae016235ea6cc/jobs/Dockerfile#L1-L5)); the gate derives a rule-data path outside `backend/` ([gate.py:16-26](https://github.com/knarayanareddy/redflag-eu-compliance/blob/ae6c6ccc6c5d41da2fa9f97b544ae016235ea6cc/backend/app/gate/gate.py#L16-L26)). The image may not locate required assets; packaging behavior was not tested. The module does contain a Uvicorn entry point ([main.py:306-309](https://github.com/knarayanareddy/redflag-eu-compliance/blob/ae6c6ccc6c5d41da2fa9f97b544ae016235ea6cc/backend/app/main.py#L306-L309)). Build and probe an approved isolated image before choosing deployment. Confidence medium.
- **RF-05 — Medium, owner decision / unverified risk.** The dev server binds `0.0.0.0` ([vite.config.ts:7-15](https://github.com/knarayanareddy/redflag-eu-compliance/blob/ae6c6ccc6c5d41da2fa9f97b544ae016235ea6cc/frontend/vite.config.ts#L7-L15)); sampled API route signatures show no auth dependency ([main.py:47-81](https://github.com/knarayanareddy/redflag-eu-compliance/blob/ae6c6ccc6c5d41da2fa9f97b544ae016235ea6cc/backend/app/main.py#L47-L81)). Actual listening interfaces, reverse-proxy protection, tenant isolation, retention and logging were not inspected. Treat remote exposure as a design decision, not an established breach. Confidence high on sampled code; deployment unknown.
- **RF-06 — High, conditional static risk; legal abstention boundary.** `/v1/info` reports `legal_compliance_verdicts_enabled: False` ([main.py:52-59](https://github.com/knarayanareddy/redflag-eu-compliance/blob/ae6c6ccc6c5d41da2fa9f97b544ae016235ea6cc/backend/app/main.py#L52-L59)), but that disclosure does not enforce `_screen_verdict`. Verified-looking rules accept PRESENT fields, and sufficiently confident ABSENT fields can produce blocking or major findings and non-abstaining `WOULD_BE_SUPPRESSED` or `AT_RISK` outcomes when no rule is unknown ([main.py:146-210](https://github.com/knarayanareddy/redflag-eu-compliance/blob/ae6c6ccc6c5d41da2fa9f97b544ae016235ea6cc/backend/app/main.py#L146-L210)). `rule_is_verified` checks metadata and provenance values' presence, not independent legal validity ([gate.py:44-63](https://github.com/knarayanareddy/redflag-eu-compliance/blob/ae6c6ccc6c5d41da2fa9f97b544ae016235ea6cc/backend/app/gate/gate.py#L44-L63)). The pinned handler calls this function; current rule data and deployed behavior were not verified, so this is not a claim of an active legal verdict. Enforce abstention before editing rule metadata, with synthetic end-to-end negative controls. Confidence high on the conditional static path.
